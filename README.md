# iOS 相簿备份管理 TUI

把 iPhone「照片」App 里的**虚拟相簿结构**（自建相簿、收藏、隐藏、视频……）按原样导出到电脑的命令行工具。在 Windows 上只用一根 USB 线，不需要 iTunes，也不用像 DCIM/PTP 文件浏览器那样手动翻文件夹——它读取 iPhone 照片库数据库 `Photos.sqlite`，还原出你在手机里看到的相簿，再按相簿导出原始照片/视频文件。

当前版本：**v1.1**（更新内容见文末）

## 工作原理

```
iPhone ──USB──> pymobiledevice3（Python 库，进程内直连）
                   │
                   ├─ 1. 拉取 PhotoData/Photos.sqlite（相簿结构数据库）
                   ├─ 2. 解析 ZASSET / ZGENERICALBUM / Z_XXASSETS 关系表
                   │     还原出相簿列表和每个相簿包含的照片
                   └─ 3. 按数据库里的 DCIM/... 路径，逐张通过 AFC 拉取原始文件
```

关于依赖 **pymobiledevice3** 的说明（回答"requirements 里写了它，代码里却没 import？"的疑问）：

- 这个工具一直依赖 pymobiledevice3，只是 v1.0 之前把它当**外部命令行**调用（每个文件启动一次 `pymobiledevice3 afc pull` 子进程），Python 代码里没有 `import` 它，所以 requirements.txt 的声明看起来"半悬空"。
- **v1.0 起改为直接 import 它的 Python 接口**：整个导出过程只建立一条 USB 服务连接，拉取文件时边下载边计算哈希。实测比旧的子进程方式快一个数量级（旧方式每个文件要白等 1.5~4 秒的进程启动）。
- 如果 Python 库导入失败，程序会自动退回旧的命令行方式（慢但可用）。

工具会额外合成这些系统分类相簿：

- `全部照片视频`、`照片`、`视频`
- `收藏`（手机里标过心的）
- `隐藏`（手机里隐藏过的）

## 环境要求

| 项目 | 要求 |
|------|------|
| 操作系统 | Windows 10 及以上（也兼容 macOS/Linux，但主要在 Windows 测试） |
| Python | 3.10 及以上（推荐 3.11+；实测 3.13） |
| USB 通信 | 安装一次 [iTunes](https://www.apple.com/itunes/) 或微软商店的「Apple Devices」，它提供 Windows 上的 USB 驱动；之后不需要开着 iTunes |
| 手机端 | iOS 15~18（更高版本 Apple 若调整数据库结构，以脚本启发式解析为准） |

## 安装

```powershell
# 在本目录下执行
py -m pip install -r requirements.txt
```

这条命令会安装 `pymobiledevice3`（>=9，Python 接口必需）。

运行方式（`-m` 后面跟模块名，不能跟文件路径）：

```powershell
python .\ios_album_backup_tui.py        # 方式一：直接运行脚本
python -m ios_album_backup_tui          # 方式二：模块方式（需在程序目录里）
```

## 快速上手

1. 用数据线连接 iPhone（首次连接会在手机上弹「信任此电脑」，点信任并输入锁屏密码）。
2. 运行程序，菜单输入 `2`：几秒到几十秒后，工具已把相簿结构数据库拉到本地（单个 `Photos.sqlite` 工作文件，每次刷新覆盖，不留历史快照）。
3. 菜单输入 `3`：查看识别出的相簿和每个相簿的照片数量。
4. 菜单输入 `4`：选择相簿编号（如 `1,3-5` 或 `all`）、选去重策略、选目录分层方式，开始导出。导出过程中每个文件实时显示文件名、大小和速度。
5. 导出结果在 `导出目录\<相簿名>\<导出日>\` 下，同时生成一份 CSV 日志。

之后再次备份时：连上手机 → 菜单 `2` 刷新元数据 → 菜单 `4` 导出，已经导过的文件会自动跳过。

## 菜单详解

| 菜单 | 功能 | 说明 |
|------|------|------|
| `1` | 检查 USB 连接 | 列出当前连接的设备；看不到设备时检查数据线/解锁/信任 |
| `2` | 获取相簿元数据 | 从手机读取 Photos.sqlite，覆盖本地工作副本（几秒到几十秒） |
| `3` | 查看相簿 | 列出所有相簿/分类及照片数 |
| `4` | 按相簿导出 | 核心功能，见下文「导出」 |
| `5` | 导出记录/重复统计 | 查看 SQLite 索引的汇总、按哈希找重复文件 |
| `6` | 生成待删除清单 | 生成 CSV 让你对照手机手动删除，**本工具永远不会删除手机上的文件** |
| `7` | 设置目录 | 修改导出/元数据/索引库位置 |
| `0` | 退出 | |

## 导出（菜单 4）的三个选择

**① 选相簿**：输入编号，支持 `1,3-5` 区间写法和 `all`。

**② 去重策略**（配合本地 SQLite 索引，跨次运行生效）：

| 策略 | 行为 |
|------|------|
| 1（默认推荐） | 同一相簿导出过就跳过；同一文件在别的相簿仍会导出 |
| 2 | 只要任何相簿导出过，任何地方都跳过 |
| 3 | 只要任何相簿导出过，仍复制，但文件名加 `__DUP` |

跳过的文件会在 CSV 里写明之前导出的时间、路径和次数。去重的依据是**资产 GUID + 手机内路径**，文件改名不影响识别。

**③ 目录日期分层**（默认：`相簿名/导出日/`）：

| 方式 | 目录结构 |
|------|----------|
| 1（默认） | `相簿名/导出当天日期/`——当天导出的同相簿文件都在同一目录 |
| 2 | `相簿名/拍摄日期/`——按照片/视频的原始拍摄日期分目录 |
| 3 | `相簿名/`——不分层 |

示例（默认方式）：

```
导出目录/
└─ 家庭/
   └─ 2026-11-15/            ← 导出当天
      ├─ IMG_1234.JPEG
      ├─ IMG_1234.AAE        ← 该照片的编辑记录（如有）
      └─ IMG_1235.MOV
```

Live Photo 的视频部分（`.MOV`）和照片编辑记录（`.AAE`）会作为附属文件一起导出。

## 导出过程能看到什么

- 每个文件拉取时实时显示一行：文件名、大小、耗时、平均速度，大文件会在同一行内刷新进度：

  ```
    ↳ IMG_5678.MOV  612.3MB/1.2GB  48.1s  13.1MB/s
    ↳ IMG_5679.JPEG  3.2MB  0.4s  8.0MB/s
    已处理 50/965：复制 32，重复 0，跳过 18，缺失 0
  ```

- 每 50 个资产打一行小计；结束后显示总耗时。
- 每次导出在导出目录下生成 `export_log_YYYYMMDD_HHMMSS.csv`，记录每个文件的状态（`copied` / `duplicate-copied` / `skipped` / `missing` / `sidecar-failed`）、来源、哈希等。日志边导出边写盘，**中途断开手机或 Ctrl+C 中断，已完成部分不会丢**，恢复后直接重跑即可。

## 导出日志与本地索引

跨次运行的长期记录在索引数据库（默认 `ios_album_backup_index.sqlite`，位置可在菜单 `7` 修改）：

- `media_backup`：每个唯一手机媒体一行（资产标识、大小、sha256、首次/最近导出时间、最近存放路径、累计次数）
- `album_backup`：某媒体曾导出到哪个相簿（同一相簿重复导出只更新计数，不堆数据）
- `backup_runs`：每次运行的汇总统计（含中断标记）

索引里存放的是**相对导出目录的路径**，整个数据目录搬到哪里都不会失效。

## 目录布局

默认所有数据都放在程序所在目录的下一级（可在菜单 `7` 修改，例如集中放到 `图片\iphone_back`）：

```
数据目录/
├─ Photos.sqlite               ← 相簿结构工作副本（菜单 2 每次刷新覆盖）
├─ ios_album_backup_index.sqlite  ← 导出索引（个人数据，勿外传）
├─ export/                     ← 导出的照片/视频（导出根目录）
│  └─ export_log_*.csv         ← 导出日志
└─ ios_photo_metadata/         ← 程序目录下的元数据默认位置
```

## 隐私说明

- 工具**只在本机工作**，不上传任何数据到网络；与手机通信也只走 USB。
- 索引数据库、导出目录、`Photos.sqlite` 工作副本里包含你的照片文件名、路径、时间等个人信息。**这些文件不会被提交进本仓库**（见 `.gitignore`），自行拷贝项目时也请注意不要外传。
- 本仓库源码本身不含任何设备名、UDID、照片信息；工具在运行中也不会把设备名/UDID 写入任何文件。

## 已知限制

- **不会删除手机上的任何东西**。iOS 没有通过 USB 暴露"按 Photos 相簿安全删除"的公开接口，直接删 DCIM 文件会让照片库失配。菜单 `6` 只生成对照清单。
- 这不是整机备份/镜像。v1.1 已移除「含媒体逻辑备份」备用方案；需要完整备份请使用 iTunes/访达或 iCloud。
- 开启 iCloud 照片 + 「优化 iPhone 储存空间」时，本地没有原片的资产会标记为 `missing`。
- Apple 会随 iOS 版本调整 `Photos.sqlite` 结构。脚本用启发式方式定位资产表和相簿关系表，覆盖常见版本，但不保证未来所有版本。
