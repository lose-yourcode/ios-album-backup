# iOS 相簿备份管理 TUI

把 iPhone「照片」App 里的**虚拟相簿结构**（自建相簿、收藏、隐藏、视频……）按原样导出到电脑的命令行工具。在 Windows 上支持 **USB 数据线**与 **Wi-Fi 无线连接**，不需要开着 iTunes，也不用像 DCIM/PTP 文件浏览器那样手动翻文件夹——它读取 iPhone 照片库数据库 `Photos.sqlite`，还原出你在手机里看到的相簿，再按相簿导出原始照片/视频文件。

当前版本：**v1.2**（更新内容见文末）

## 工作原理

```
iPhone ──USB / Wi-Fi──> pymobiledevice3（Python 库，进程内直连）
                           │
                           ├─ 1. 拉取 PhotoData/Photos.sqlite（相簿结构数据库）
                           ├─ 2. 解析 ZASSET / ZGENERICALBUM / Z_XXASSETS 关系表
                           │     还原出相簿列表和每个相簿包含的照片
                           └─ 3. 按数据库里的 DCIM/... 路径，逐张通过 AFC 拉取原始文件
```

关于依赖 **pymobiledevice3** 的说明（回答"requirements 里写了它，代码里却没 import？"的疑问）：

- 这个工具一直依赖 pymobiledevice3，只是 v1.0 之前把它当**外部命令行**调用（每个文件启动一次 `pymobiledevice3 afc pull` 子进程），Python 代码里没有 `import` 它，所以 requirements.txt 的声明看起来"半悬空"。
- **v1.0 起改为直接 import 它的 Python 接口**：整个导出过程只建立一条 USB / Wi-Fi 服务连接，拉取文件时边下载边计算哈希。实测比旧的子进程方式快一个数量级（旧方式每个文件要白等 1.5~4 秒的进程启动）。
- 如果 Python 库导入失败，程序会自动退回旧的命令行方式（慢但可用）。

工具会额外合成这些系统分类相簿：

- `全部照片视频`、`照片`、`视频`
- `收藏`（手机里标过心的）
- `隐藏`（手机里隐藏过的）

## 环境要求

| 项目 | 要求 |
|------|------|
| 操作系统 | Windows 10 及以上（也兼容 macOS/Linux，但主要在 Windows 测试） |
| Python | 3.10 及以上（推荐 3.11+；实测 3.13） |
| USB 通信 | 安装一次 [iTunes](https://www.apple.com/itunes/) 或微软商店的「Apple Devices」，它提供 Windows 上的 USB 驱动；之后不需要开着 iTunes |
| 手机端 | iOS 15~18（更高版本 Apple 若调整数据库结构，以脚本启发式解析为准） |

## 安装

```powershell
# 在本目录下执行
py -m pip install -r requirements.txt
```

这条命令会安装 `pymobiledevice3`（>=9，Python 接口必需）。

运行方式（`-m` 后面跟模块名，不能跟文件路径）：

```powershell
python .\ios_album_backup_tui.py        # 方式一：直接运行脚本
python -m ios_album_backup_tui          # 方式二：模块方式（需在程序目录里）
```

## 快速上手

### 方式 A：USB 有线连接
1. 用数据线连接 iPhone（首次连接会在手机上弹「信任此电脑」，点信任并输入锁屏密码）。
2. 运行程序，直接菜单输入 `3`（或先输入 `2` 刷新并预览相簿列表）：几秒到几十秒后，工具会把相簿结构数据库 `Photos.sqlite` 拉到本地并列出所有相簿。
3. 选择相簿编号（如 `1,3-5` 或 `all`）、选去重策略、选目录分层方式，开始导出。导出过程中每个文件实时显示文件名、大小和速度。
4. 导出结果在 `导出目录\<相簿名>\<导出日>\` 下，同时生成一份 CSV 日志。

### 方式 B：Wi-Fi 无线连接（无需插 USB 线）
1. **首次开启（只需插一次 USB）**：连上 USB 线后运行程序，进入菜单 `1`（连接管理与设备选择）→ 选择 `2. 开启 iPhone Wi-Fi 同步`，工具会自动完成信任配对、打开 iOS 的 `EnableWifiConnections` 开关，并缓存本机配对记录。
2. **拔掉数据线**：确保 iPhone 与电脑在同一个 Wi-Fi 局域网（且路由器未开启 AP 隔离）。
3. 直接执行菜单 `3` 按相簿导出（未加载时会自动先连手机读取 `Photos.sqlite`），或先执行菜单 `2` 预览相簿列表。默认**自动模式**会在未插 USB 时自动切换为 Wi-Fi 连接；也可在菜单 `1` 指定设备、切换为「仅 Wi-Fi 无线」或配置「手动 Wi-Fi IP 直连」（当路由器屏蔽 mDNS 广播时使用）。

之后再次备份时：确保手机与电脑同处一个 Wi-Fi（或连上数据线）→ 直接菜单 `3` 导出（或先 `2` 刷新再 `3`），已经导过的文件会自动跳过。

## 菜单详解

| 菜单 | 功能 | 说明 |
|------|------|------|
| `1` | 连接管理与设备选择（USB / Wi-Fi） | 探测 USB 与 Wi-Fi 设备、多设备/多连接选择、首次开启 Wi-Fi 同步、切换连接方式与手动 IP |
| `2` | 连接手机并加载相簿 | 从手机读取最新 Photos.sqlite，覆盖本地工作副本并直接列出相簿（连接复用至导出） |
| `3` | 按相簿导出原始文件 | 核心功能（未连接时自动先加载相簿），支持 Wi-Fi 瞬断自动重连，见下文「导出」 |
| `4` | 查看导出记录/重复统计 | 查看 SQLite 索引的汇总、按哈希找重复文件 |
| `5` | 生成待删除清单 | 生成 CSV 让你对照手机手动删除，**本工具永远不会删除手机上的文件** |
| `6` | 设置目录与连接 | 修改导出/元数据/索引库位置、连接方式与手动 Wi-Fi IP |
| `0` | 退出 | |

## 导出（菜单 3）的三个选择

**① 选相簿**：输入编号，支持 `1,3-5` 区间写法和 `all`。

**② 去重策略**（配合本地 SQLite 索引，跨次运行生效）：

| 策略 | 行为 |
|------|------|
| 1（默认推荐） | 同一相簿导出过就跳过；同一文件在别的相簿仍会导出 |
| 2 | 只要任何相簿导出过，任何地方都跳过 |
| 3 | 只要任何相簿导出过，仍复制，但文件名加 `__DUP` |

跳过的文件会在 CSV 里写明之前导出的时间、路径和次数。去重的依据是**资产 GUID + 手机内路径**，文件改名不影响识别。

**③ 目录日期分层**（默认：`相簿名/导出日/`）：

| 方式 | 目录结构 |
|------|----------|
| 1（默认） | `相簿名/导出当天日期/`——当天导出的同相簿文件都在同一目录 |
| 2 | `相簿名/拍摄日期/`——按照片/视频的原始拍摄日期分目录 |
| 3 | `相簿名/`——不分层 |

示例（默认方式）：

```
导出目录/
└─ 家庭/
   └─ 2026-11-15/            ← 导出当天
      ├─ IMG_1234.JPEG
      ├─ IMG_1234.AAE        ← 该照片的编辑记录（如有）
      └─ IMG_1235.MOV
```

Live Photo 的视频部分（`.MOV`）和照片编辑记录（`.AAE`）会作为附属文件一起导出。

## 导出过程能看到什么

- 每个文件拉取时实时显示一行：文件名、大小、耗时、平均速度，大文件会在同一行内刷新进度：

  ```
    ↳ IMG_5678.MOV  612.3MB/1.2GB  48.1s  13.1MB/s
    ↳ IMG_5679.JPEG  3.2MB  0.4s  8.0MB/s
    已处理 50/965：复制 32，重复 0，跳过 18，缺失 0
  ```

- 每 50 个资产打一行小计；结束后显示总耗时。
- 每次导出在导出目录下生成 `export_log_YYYYMMDD_HHMMSS.csv`，记录每个文件的状态（`copied` / `duplicate-copied` / `skipped` / `missing` / `sidecar-failed`）、来源、哈希等。日志边导出边写盘，**中途断开手机或 Ctrl+C 中断，已完成部分不会丢**，恢复后直接重跑即可。

## 导出日志与本地索引

跨次运行的长期记录在索引数据库（默认 `ios_album_backup_index.sqlite`，位置可在菜单 `6` 修改）：

- `media_backup`：每个唯一手机媒体一行（资产标识、大小、sha256、首次/最近导出时间、最近存放路径、累计次数）
- `album_backup`：某媒体曾导出到哪个相簿（同一相簿重复导出只更新计数，不堆数据）
- `backup_runs`：每次运行的汇总统计（含中断标记）

索引里存放的是**相对导出目录的路径**，整个数据目录搬到哪里都不会失效。

## 目录布局

默认所有数据都放在程序所在目录的下一级（可在菜单 `6` 修改，例如集中放到 `图片\iphone_back`）：

```
数据目录/
├─ Photos.sqlite               ← 相簿结构工作副本（菜单 2 每次刷新覆盖）
├─ ios_album_backup_index.sqlite  ← 导出索引（个人数据，勿外传）
├─ export/                     ← 导出的照片/视频（导出根目录）
│  └─ export_log_*.csv         ← 导出日志
└─ ios_photo_metadata/         ← 程序目录下的元数据默认位置
```

## 隐私说明

- 工具**只在本机工作**，不上传任何数据到互联网；与手机通信只走本机 USB 或同一局域网下的 Wi-Fi（加密的 Apple Lockdown/AFC 通道）。
- 索引数据库、导出目录、`Photos.sqlite` 工作副本里包含你的照片文件名、路径、时间等个人信息。**这些文件不会被提交进本仓库**（见 `.gitignore`），自行拷贝项目时也请注意不要外传。
- 本仓库源码本身不含任何设备名、UDID、照片信息；工具在运行中也不会把设备名/UDID 写入任何项目文件（仅可由用户手动配置局域网 IP）。

## 已知限制

- **不会删除手机上的任何东西**。iOS 没有通过 USB/Wi-Fi 暴露"按 Photos 相簿安全删除"的公开接口，直接删 DCIM 文件会让照片库失配。菜单 `5` 只生成对照清单。
- 本工具只按相簿直连导出照片与视频，不做整机备份（整机备份请使用 iTunes/访达或 iCloud）。
- 开启 iCloud 照片 + 「优化 iPhone 储存空间」时，本地没有原片的资产会标记为 `missing`。
- Apple 会随 iOS 版本调整 `Photos.sqlite` 结构。脚本用启发式方式定位资产表和相簿关系表，覆盖常见版本，但不保证未来所有版本。

## 更新日志

### v1.2 (2026-11-26)

- 新增 **Wi-Fi 无线同步连接**支持：不再必须插着 USB 线导出。
  - 支持四种连接方式：`自动（USB 优先，未插线走 Wi-Fi）`、`仅 Wi-Fi 无线`、`仅 USB 有线`、`手动 Wi-Fi IP 直连（TCP 62078）`。
  - Wi-Fi 自动发现依次尝试 `usbmux Network`、Windows `dns-sd` / Bonjour (`_apple-mobdev2._tcp.local.`)、以及用户可选配置的手动局域网 IP；兼容私有 Wi-Fi 地址下按配对记录匹配，并为直连 TCP 维持 `com.apple.mobile.heartbeat` 心跳以保证 AFC 稳定不断开。
- 菜单 `1` 升级为「连接管理与设备选择」：列出全部 USB / Wi-Fi 端点并支持多设备或指定 USB/Wi-Fi 选择（菜单 `2` 检测到多台可用设备时也会提示选择）；同时支持插一次 USB 线一键开启 `EnableWifiConnections`、切换连接模式与设置手动 IP。
- 菜单 `2` 改为单次建立 AFC 连接并直接列出相簿（连接直接复用至导出），移除冗余的单独「查看相簿」菜单项；直接选菜单 `3`（导出）或 `5`（生成待删除清单）且尚未连接时也会自动先连接并加载相簿，主菜单精简为 6 项。
- 导出过程增加 Wi-Fi 瞬断自动重连与单次重试；重连仍失败时安全中断并保存 CSV 与索引库进度。
- 彻底清理旧版完整备份（`backup2`）遗留的配置键、失效分支及过时提示文案。
